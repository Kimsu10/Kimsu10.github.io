## branch 생성

아래의 명령어를 터미널에 입력하면 브랜치명으로 새로운 브랜치가 생성된다.

# 6. git에 올리기

코드를 작성하고 나면 git에 올려야할텐데 처음 사용했을때 가장많이하던 실수가 이부분이 아닐까싶다.
바로..

## 0-1) branch 확인하기

올리기전에 현재 내가 어떤 브랜치에있는지 꼭 확인하자.
처음 git을 사용해봤을때 나의 브랜치에 누군가 자신의 작업물을 올려 계속해서 충돌난적이있는데 해결하느라 정말 고생했다.
또 main이나 master브랜치에 바로 push 할 경우 회사라고 생각하면 아찔하다.

현재의 브랜치를 확인하는 방법은 git branch를 입력하면 된다.

```
git branch
```

만약 브랜치를 나눠서 작업중이였는데 현재위치가 master(main)이라면
브랜치를 변경하고 add를 해야한다.

## 0-2) branch 변경하기

```
git checkout 브랜치명
```

## 1. git add

```
git add .
```

git add만 치거나 git add.을 치거나해서 안올라간 경우가 많았다.

## 2. git commit

git add를 하면 어떤 것을 했는지 commit 로그를 남겨야한다.

```
git commit -m "커밋 메세지"
```

## 3. git push

이제 깃에 올리면 된다.

```
git push origin main

git push origin branch이름
```

# 7. pull & request

이미지를 찾아야한다..

내가보낸 PR이 merge되면 다시 내 로컬의 main에 업데이트를 해주어야한다.

# 8. git merge

## git pull

프로젝트 폴더의 터미널로 돌아와서 git상에 merge된 master(main)을 pull해온다.

```
git pull origin master(main)
```

이때 나의 브랜치위치는 master나 main이여야한다.
![](https://velog.velcdn.com/images/kimsu10/post/fa07fceb-da53-4d5a-b9f7-1b373d71cd8a/image.png)

![](https://velog.velcdn.com/images/kimsu10/post/d4901f56-4f54-49de-8f98-e39bc3cd37c5/image.png)
위의 이미지처럼 나의 로컬의 master(main)브랜치가 업데이트 되면
다시 작업하던 브랜치로 바꿔주고 merge(병합)하면 된다.

```
git checkout 작업하던 브랜치

git merge origin master(main)
```

![](https://velog.velcdn.com/images/kimsu10/post/7f29f22e-6093-4f14-bf70-e55d9aa2f86a/image.png)
그러면 아래와 같이 merge 커밋에관한 이미지가 뜨는데 `:wq`를 입력하면 저장하고 나오자.
![](https://velog.velcdn.com/images/kimsu10/post/9463d2c6-3933-400a-b48f-9dd9984e1c02/image.png)
그러면 merge도 완료!
![](https://velog.velcdn.com/images/kimsu10/post/88d0fe39-b73b-4596-9056-34f8ab866639/image.png)

이러한 작업을 반복해나가면서 사용하면된다.
