> [NestJS Document](https://docs.nestjs.com/first-steps)

1. nestjs는 nodejs를 기반으로하기때문에 우선 nodejs를 설치해야한다.

   > [NodeJs 공식사이트](https://nodejs.org/ko/download)
   > 최신버전을다운받는게좋다고하는데 안정적인버전을 원한다면 LTS를 선택하면 된다.
   > [NodeJs 설치글]()
   > nodejs를 설치하면 기본적으로 npm(node package manager)가 함께 설치되기때문에 npm을 바로 사용할 수 있다.

2. 우선 NestJS서버를 구성하기위해 @nestjs/cli를 설치해야한다.

```
npm i -g @nestjs/cli
```

3. 설치 후 초기화하기

```
nest new project-name
```

위의 코드를 터미널에 아래의 이미지처럼 패키지 매니저를 선택하는 창이 나온다.

설치가 완료되면 boilerplate 코드가 생성된다.
![](https://velog.velcdn.com/images/kimsu10/post/534224d4-a996-43e2-bc12-c897016b0045/image.png)
package.json파일을 어떻게 똑같이 만들어야하나했는데 이미 만들어져있고 tsconfig도 있다.
프로젝트명의 디렉토리가 생성되고, 노드모듈과 몇몇 보일러플레이트 파일들이 설치된다고 읽긴했는데 직접보니까 너무 신기하다..!

tsconfig.json에 `"esModuleInterop": true` 이라는 옵션을 추가해주자.
타입스크립트는 기본적으로 esModuleInterop property 옵션이 false로 설정되어있다.
이경우 타입스크립트가 import하는 모듈이 commonjs(require)로 설정되어있는데 es6문법(import)으로 가져올때 오류가 발생한다.
이 옵션을 true로 바꾸면 require과 import 모두 사용할 수 있다.

프로젝트에 필요한 파일들과 패키지들 설치가 완료되었으니 터미널에 `nest`를 입력하면 사용가능한 커맨드를 알려준다.
![](https://velog.velcdn.com/images/kimsu10/post/2c79edad-f8aa-429c-b52c-9a80107efae3/image.png)

서버가 돌아가는지 확인하기
package.json의 scripts를 보면 서버를 키는 명렬어를 확인할 수 있다.
![](https://velog.velcdn.com/images/kimsu10/post/22693349-6720-4f06-ba7b-78d74aa21e15/image.png)

```
npm run start:dev
```

![](https://velog.velcdn.com/images/kimsu10/post/f008cb65-ef37-4162-9f6a-029ba0f01029/image.png)
응? 왜 안돼..? 계속 scripts 리스트에 실행어가 없다고해서 내가 스크립트도 못읽는 바보가 된건가 진지하게 의심하고 있었다.
예~전에 package.json이있는폴더에 명령어를 안쳤던거같아서 '설마..🤔?'라고 생각하며 현재위치를 찾아보니 터미널에는 ren9라고 프로젝트 폴더명이 표시되어있지만 실제로는 ren9폴더 안에 있지않았다. 오우 노우...와이...
프로젝트 폴더로 이동후 다시 npm run start:dev를 입력하니 서버의 실행을 확인할 수 있었다.
